# Gcal-picup — 外部との日程調整最適化ツール

会社の Google Workspace 環境で、外部との打合せ日程調整を効率化する Google Apps Script (GAS) Web アプリです。

## できること

1. **社内メンバーの空き状況を週表示で確認**(自分の予定+メンバーの予定ありの時間帯をオーバーレイ表示)
2. **候補日程を複数ピックアップ**(所要時間を選んで空きセルをクリック)
3. **候補を自分のカレンダーに「仮予定」として登録**して枠を確保(`【仮】○○社 打合せ (1/3)` のようなグレー色の予定になります)
4. **候補日程を整形テキストでコピー**して相手にメール送付(例: `・7/28(月) 10:00〜11:00`)
5. **確定日を選ぶと、他の仮予定は自動削除**され、確定予定のタイトルが正式化されます(オプションでメンバーを招待)

設計上のポイント:

- **GAS 標準サービスのみで動作**します。Advanced Google Services の有効化や GCP プロジェクトの作成は不要です(会社の API 制限を回避するため)。
- メンバーの空き状況は 2 段構えで取得します:
  - まず `CalendarApp`(カレンダー購読)。詳細共有されている相手は予定タイトルまで表示。
  - 取れない場合は freeBusy REST API を `UrlFetchApp` で直接呼び出し(「予定の有無のみ公開」の相手でも時間帯が取れます)。
  - どちらも不可の相手は「⚠ アクセス不可」表示になり、ツール全体は動き続けます。
- メンバーの招待タイミングは登録時に選べます:
  - **確定時にのみ招待**(デフォルト): 仮予定の段階では相手のカレンダーを埋めません
  - **仮予定の段階で枠を確保**: 候補全部がメンバーのカレンダーにも登録されます(確定時に選ばれなかった候補は自動的にメンバー側からも消えます)。ただし候補の数だけ招待通知が届く点に注意

## ファイル構成

```
src/
├── appsscript.json  # マニフェスト(OAuthスコープ・Webアプリ設定・タイムゾーン)
├── main.gs          # doGet / 初期化 / メンバー設定
├── calendar.gs      # 自分の予定取得+メンバー空き状況(2段フォールバック)
├── candidates.gs    # 候補セット管理(仮予定の登録・確定・取り下げ・テキスト生成)
├── index.html       # 画面構造
├── style.html       # CSS
└── app-js.html      # クライアントJS
```

`src/` のファイルと GAS エディタ上のファイルは 1 対 1 対応です。**リポジトリが常に正、GAS エディタは反映先**として運用してください。

## セットアップ

### 1. GAS プロジェクトの作成

1. [script.google.com](https://script.google.com) を開き、「新しいプロジェクト」を作成(名前: `Gcal-picup` など)
2. エディタ左の「プロジェクトの設定」→「`appsscript.json` マニフェスト ファイルをエディタで表示する」を ON

### 2. コードの反映 — 方法A: clasp(推奨、1回だけ試す)

```bash
npm install -g @google/clasp
clasp login                          # 会社のGoogleアカウントでOAuth
# https://script.google.com/home/usersettings で「Google Apps Script API」をONにする
cp .clasp.json.example .clasp.json   # scriptId を自分のプロジェクトIDに書き換える
clasp push
```

`clasp login` や Apps Script API の有効化が**会社の制限でブロックされた場合は深追いせず、方法Bに切り替えてください**(組織の OAuth アプリ制限は個人では解決できません)。

### 2'. コードの反映 — 方法B: 手動コピペ

GAS エディタで以下のファイルを作成し、`src/` の同名ファイルの内容を貼り付けます:

| リポジトリ | GASエディタでの作成方法 |
|---|---|
| `appsscript.json` | プロジェクト設定でマニフェスト表示をONにして編集 |
| `main.gs` / `calendar.gs` / `candidates.gs` | 「+」→ スクリプト(拡張子 .gs は自動付与) |
| `index.html` / `style.html` / `app-js.html` | 「+」→ HTML(拡張子 .html は自動付与) |

ファイル名は**拡張子を除いた部分を一致**させてください(`include('style')` 等で参照しているため)。

### 3. 動作検証(Phase 0: 会社制限の洗い出し)

1. エディタで `test_whoAmI` 関数を選択して「実行」
2. 初回は認可ダイアログが出ます。「このアプリは確認されていません」と出たら「詳細」→「(プロジェクト名)に移動」で続行(自分で作った同一ドメインのスクリプトなら通常続行できます)
3. ログに自分のメールアドレスと今日の予定件数が出れば OK

**ここでエラーが出た場合**(認可がブロックされる等)は、エラーメッセージを控えて相談してください。管理者による制限の可能性があります。

### 4. Web アプリとしてデプロイ

1. 「デプロイ」→「新しいデプロイ」→ 種類: **ウェブアプリ**
2. 「次のユーザーとして実行」: **自分** / 「アクセスできるユーザー」: **自分のみ**
3. デプロイして発行された URL を開く

開発中は「デプロイをテスト」の `/dev` URL を使うと、コード保存だけで最新版が反映されて便利です(本番 `/exec` はデプロイ更新が必要)。

## 使い方

1. ヘッダーの「設定」から社内メンバー(メールアドレス+表示名)を登録
2. 週表示グリッドで空き状況を確認(チップのクリックでメンバーの表示 ON/OFF)
3. 所要時間(30〜120分)を選び、空きセルをクリックして候補を追加(クリックで解除)。クリックした位置が打合せの開始時刻になります
   - **訪問の場合**は「前後の移動時間」(30/60/90分)を選ぶと、カレンダー上は移動込みの枠(例: 60分打合せ+前後60分=180分)で仮予定が確保されます。相手に送るテキストには打合せ時間のみが記載されます。仮予定・確定予定のタイトルには `【移動±60分込】` が付きます
4. 件名を入力して「仮予定として登録」→ カレンダーに `【仮】` 予定が作成され、送付用テキストが表示される
   - 「仮予定の段階でメンバーの枠も確保する」を ON にすると、チェックしたメンバー全員のカレンダーにも候補が登録されます(招待通知が候補の数だけ届きます)
5. 「コピー」してメールに貼り付けて相手に送付
6. 相手から返答が来たら、候補セット一覧の「この日で確定」をクリック → 他の仮予定は自動削除され、確定予定のタイトルが正式化されます(確定時にメンバー招待も選択可)
7. 全滅した場合は「取り下げ」で仮予定を一括削除

## トラブルシューティング(会社制限で詰まりやすいポイント)

| 症状 | 原因と対処 |
|---|---|
| 初回認可で「管理者にお問い合わせください」 | 組織が GAS の OAuth スコープを制限。エラー文言を控えて相談してください。`appsscript.json` の `script.external_request` 行を削除して再試行すると、freeBusy フォールバックなし(詳細共有メンバーのみ表示)で動く場合があります |
| メンバーが全員「⚠ アクセス不可」 | (1) 相手がカレンダーを一切公開していない (2) `UrlFetchApp` が制限されている。GAS エディタで `test_getMembersFreeBusy` を実行し、ログの `error` を確認してください |
| メンバーの予定にタイトルが出ない | 相手が「予定の有無のみ公開」設定。時間帯のみ表示されます(正常動作) |
| コピーが失敗する | サンドボックス制限。テキストエリアが自動表示されるので手動コピーしてください |
| 確定時に「既に削除されていました」の注意 | 仮予定をカレンダー上で手動削除済み。処理は続行されるので問題ありません |
| 招待メールが飛ばない/飛んでしまう | `CalendarApp.addGuest` は通知の制御ができません。相手側の通知設定に依存します |

### 既知の制約

- 候補は単発予定のみ(繰り返し予定は対象外)
- 週表示は月〜金の 8:00〜20:00、30 分刻み
- 全日予定は空き状況の判定から除外しています(終日の「外出」等はグリッドに出ません)
- ブラウザのタイムゾーンが Asia/Tokyo であることを前提にしています

## 開発メモ

- サーバー・クライアント間の日時は常に ISO8601 文字列で受け渡し(`Date` オブジェクトを直接渡さない)
- 候補セットの台帳は `UserProperties`(キー: `grp_<uuid>`)が正。各仮予定のタグ `gcalPicupGroupId` は色分け表示・手動削除検知用
- デバッグは「UI」と「権限」を分離する: サーバー層は GAS エディタから `test_` 関数を直接実行してログで確認
- 開発中のゴミ掃除: `test_cleanupAllCandidates()`(タグ付き仮予定を全削除+台帳リセット)
